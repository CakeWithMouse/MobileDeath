# Установка БД и запуск MobileDeath

Все пути и команды ниже указаны относительно корня `MobileDeath`, а не каталога `docs`.

## Быстрый старт на Windows x64

1. Установите **Node.js 22 или новее с npm** с [официального сайта](https://nodejs.org/en/download). После установки откройте новое окно терминала. Проверьте `node --version` и `npm --version`.
2. Склонируйте или распакуйте проект в каталог, в который у вас есть право записи.
3. Из корня проекта выполните:

   ```powershell
   .\setup-local.bat
   ```

   Команда устанавливает npm-зависимости, скачивает MariaDB 11.8.9 для Windows x64 из официального архива, проверяет SHA-256, распаковывает сервер и создаёт новую локальную БД. Генерируются отдельные случайные пароли root и приложения. В новую БД автоматически применяется `ServerPart/schema.sql`, создаётся `ServerPart/.env`. Интернет нужен при первой установке.

4. Запустите БД и API:

   ```powershell
   .\start-local.bat
   ```

5. Проверьте API:

   ```powershell
   Invoke-RestMethod http://127.0.0.1:3005/health
   ```

БД слушает `127.0.0.1:3307`, API — `127.0.0.1:3005`. `/health` проверяет только HTTP; проверка настоящей БД — регистрация/вход по инструкции ниже. После setup БД уже работает; start-local безопасно использует запущенный экземпляр.

MariaDB запускается фоновым процессом без окна, без регистрации службы Windows, автозагрузки, Docker и изменения системного PATH. После перезагрузки компьютера достаточно снова выполнить start-local.bat. Данные сохраняются на диске.

Если порт 3307 занят, **до первой установки** выберите другой:

```powershell
$env:LOCAL_DB_PORT = '3317'
.\setup-local.bat
```

После установки порт сохранён в локальных настройках; последующее изменение LOCAL_DB_PORT не перенастраивает существующую БД.

## Повторный запуск и остановка

- `setup-local.bat` — первоначальная установка и проверка конфигурации. Повторный запуск не пересоздаёт таблицы и не удаляет данные.
- `start-local.bat` — поднимает локальную БД и запускает API в текущем окне.
- Ctrl+C в окне сервера — останавливает API. БД продолжает работать.
- `stop-database.bat` — корректно останавливает локальную БД, сохраняя данные. Сначала остановите API.
- Старый `start-server.bat` по-прежнему запускает только API, используя уже настроенную БД.

Из ServerPart доступны отдельные команды:

```powershell
npm run db:setup
npm run db:start
npm run db:status
npm run db:stop
npm run db:backup
```

Установщик не перезаписывает существующий `.env`, направленный на другую БД. При таком конфликте сначала сохраните прежнюю конфигурацию и решите, какой экземпляр вам нужен. Не удаляйте `.local/database/data` для исправления ошибки: там ваши данные. При частично выполненной инициализации скрипт останавливается, не очищая её автоматически.

## Что хранится в Git, а что локально

| Файл или каталог | Назначение | В Git |
| --- | --- | --- |
| ServerPart/schema.sql | Начальная структура таблиц | Да |
| ServerPart/scripts/database.js | Установка и управление локальной БД | Да |
| setup-local.bat, start-local.bat, stop-database.bat | Команды Windows | Да |
| ServerPart/.env.example | Пример настроек без пароля | Да |
| ServerPart/.env | Пароль приложения и подключение | Нет |
| .local/database/credentials.json | Пароли локального root и приложения | Нет |
| .local/database/data/ | Рабочие данные MariaDB | Нет |
| .local/database/server.log | Журнал запуска БД | Нет |
| .local/database/mariadb-11.8.9-winx64/ | Локальные бинарные файлы MariaDB | Нет |
| .local/backups/ | SQL-резервные копии | Нет |

Другим разработчикам передавайте репозиторий. Они запускают setup-local.bat и получают собственную пустую БД с собственной парой паролей. Не копируйте каталог живой БД между компьютерами; для переноса данных используйте SQL-дамп.

## Подключение к БД

Для SQL-клиента используйте host `127.0.0.1`, порт из `ServerPart/.env` (обычно 3307), БД `mobiledeath`, пользователя `mobiledeath_app` и пароль из того же файла. Пользователь приложения имеет только SELECT, INSERT, DELETE, которые нужны текущему API.

Для ручного создания таблиц, изменения структуры или импорта подключайтесь отдельно как root с rootPassword из `.local/database/credentials.json`. Не используйте root в настройках API.

Встроенный SQL-клиент из корня проекта:

```powershell
& '.\.local\database\mariadb-11.8.9-winx64\bin\mariadb.exe' --host=127.0.0.1 --port=3307 --user=root --password
```

Пароль вводится в интерактивном запросе. Учитывайте свой порт, если он отличается.

## Проверка регистрации и настоящей БД

При запущенном start-local.bat выполните в другом окне PowerShell:

```powershell
$api = 'http://127.0.0.1:3005'
$body = @{ login = 'player_1'; password = 'example-password-123' } | ConvertTo-Json
Invoke-RestMethod "$api/auth/register" -Method Post -ContentType 'application/json' -Body $body
$session = Invoke-RestMethod "$api/auth/login" -Method Post -ContentType 'application/json' -Body $body
$headers = @{ Authorization = "Bearer $($session.token)" }
Invoke-RestMethod "$api/auth/me" -Headers $headers
Invoke-RestMethod "$api/auth/logout" -Method Post -Headers $headers
```

Повторная регистрация того же логина вернёт 409; для следующей проверки используйте вход. Перезапуск БД не удаляет пользователей. После выхода старый токен должен возвращать 401.

## Если есть готовая БД или SQL-дамп


Текущая схема содержит только users/sessions. Дамп старого проекта не обязательно совместим с новым API. Установка **не импортирует произвольный дамп автоматически** и не выполняет миграций существующих таблиц.

Для просмотра чужого дампа создайте отдельную пустую БД через root-клиент, затем импортируйте его туда:

```sql
CREATE DATABASE mobiledeath_import CHARACTER SET utf8mb4;
USE mobiledeath_import;
SOURCE F:/path/to/your/dump.sql;
```

Перед импортом проверьте SQL-файл: команды USE, CREATE DATABASE, DROP и квалифицированные имена таблиц в самом дампе могут переключить цель или изменить другую БД. Пример предполагает дамп одной БД без таких переключений. Для подключения API к импортированной БД сначала сопоставьте таблицы с ServerPart/schema.sql и настройте отдельного пользователя приложения.

## Резервная копия

При запущенной БД выполните из ServerPart:

```powershell
npm run db:backup
```

Команда создаёт SQL-файл с датой в `.local/backups/`, не заменяя предыдущие файлы. Дамп делается через mariadb-dump с single-transaction. Восстанавливайте его сначала в новую отдельную БД, как описано выше; автоматической команды восстановления поверх рабочих данных нет.

## Другие ОС и уже установленная MariaDB

Автоматическая установка рассчитана на Windows x64. На Linux/macOS или при использовании существующей MariaDB создайте новую пустую БД, выполните ServerPart/schema.sql и настройте ServerPart/.env по .env.example. Затем выполните `npm ci` и `npm start` из ServerPart. Скрипты db:* управляют только экземпляром в .local/database.

## Источники и диагностика

Используются [официальный ZIP MariaDB 11.8.9](https://archive.mariadb.org/mariadb-11.8.9/winx64-packages/) и [официальная утилита инициализации Windows](https://mariadb.com/docs/server/server-management/install-and-upgrade-mariadb/installing-mariadb/installing-system-tables-mariadb-install-db/mariadb-install-db-exe). SHA-256 архива закреплён в скрипте установки.

При ошибке скачивания проверьте интернет/прокси и повторите setup. При несовпадении SHA-256 удалите только ZIP-архив, указанный в ошибке, и повторите скачивание. При ошибке старта смотрите `.local/database/server.log`. Скрипт не останавливает чужие серверы на занятом порту.

Это локальная среда разработки: БД доступна только через loopback. Для телефона используется HTTP API компьютера, а не прямое подключение к MariaDB.
